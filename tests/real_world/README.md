# Real-world script corpus

Scripts representative of patterns lush will encounter in actual use,
run through `diff_oracle` against the matching reference shell.

The corpus has two distinct bodies:

- **`curated/`** -- the original hand-written test scripts (22 as of
  2026-05-24). Each one was authored by hand to exercise a specific
  idiom. Useful as smoke tests; not statistically meaningful for
  release-readiness on their own.
- **`corpus/`** -- upstream-sourced material ingested via the harness
  in `_harness/`. Target: hundreds of scripts per shell mode, drawn
  from reputable production codebases (autoconf, bash-completion,
  oh-my-zsh, etc.). This body is what makes the scorecard a real
  readiness signal.

See [HARNESS.md](HARNESS.md) for how the corpus pipeline works.

## Layout

```
tests/real_world/
+-- curated/                 # Hand-written, one-script-per-idiom
|   +-- posix/               # POSIX-portable patterns (oracle: dash)
|   +-- bash/                # Bash-leaning idioms     (oracle: bash)
|   +-- zsh/                 # Zsh-leaning idioms      (oracle: zsh)
|   +-- lush/                # Polyglot intermix       (no oracle)
+-- corpus/                  # Upstream-sourced, harness-ingested
|   +-- posix/               # e.g. corpus/posix/autoconf/*.sh
|   +-- bash/                # e.g. corpus/bash/bash-completion/*.sh
|   +-- zsh/                 # e.g. corpus/zsh/oh-my-zsh/*.sh
|   +-- lush/
|   +-- WAIVERS.md           # Top-level ledger of every hermeticity waiver
|   +-- <bucket>/<set>/      # Per-upstream-set subdirectory
|       +-- SOURCES.md       # Upstream URL + commit per script
|       +-- *.sh             # Adapted scripts with provenance headers
+-- _harness/                # Curation tooling (ingest.sh, etc.)
+-- README.md
+-- HARNESS.md
```

Naming conventions:

- **curated/** -- `NNN_short_description.sh`, three-digit prefix
  grouped 100-199 for posix, 200-299 bash, 300-399 zsh, 400-499 lush.
- **corpus/** -- preserves the upstream filename where possible.
  Each file carries a provenance header generated by
  `_harness/header-template.sh`.

## Running

The `diff_oracle` binary reads scripts from any subdirectory; mode is
resolved by walking the path for a `posix` / `bash` / `zsh` / `lush`
segment. Both bodies feed the same scorecard.

```sh
meson compile -C build diff_oracle
meson test -C build "real-world scorecard"
```

Or directly:

```sh
find tests/real_world \( -path '*/curated/*' -o -path '*/corpus/*' \) \
    -name '*.sh' | xargs ./build/diff_oracle --lush ./build/lush
```

## Selection criteria

Scripts in either body must be:

- **Self-contained** -- no network, no `sudo`, no shared system files.
  Side effects only under `$TMPDIR`; `/tmp/<name>.pid` is fine,
  `/var/run/...` is not.
- **Deterministic** -- no timing, `$RANDOM`, `$$`, or date-dependent
  output (or stripped from the diff oracle's compare).
- **Hermetic** -- no `command -v X` checks that depend on the runner's
  PATH (stub with a fixed result); no live `git` / `curl` / `wget`.
- **Representative** -- mirror an idiom that appears in real-world
  scripts from reputable sources. Don't include adversarial or
  pathological inputs -- those go in `tests/fuzz/`.

For `corpus/` ingestion, the harness enforces these mechanically;
see [HARNESS.md](HARNESS.md).

## What "passes" means

`diff_oracle` produces JSON per script. A pass:

- `agree: true` -- stdout, stderr, and exit code match the oracle, OR
- `agree: false, allowed: true` -- a deliberate known divergence
  (curated in `tests/fuzz/differential/known_divergences.txt`).

Anything else is a punch-list item.

## What the pass rate means

Right now (2026-05-24): **22 curated scripts. 100% pass means 22-of-22
pass.** That is a smoke test. It is not a statistical claim about
real-world readiness.

The `corpus/` body exists to change that -- once it carries hundreds
of upstream-sourced scripts, pass rate over the combined body becomes
a defensible readiness signal. Until then, treat the curated pass
rate as a regression guard, not as proof of fitness.

## Adding scripts manually (curated/)

For each addition under `curated/`:

1. The script runs cleanly under its oracle (`dash script.sh` for posix,
   `bash script.sh` for bash, `zsh script.sh` for zsh).
2. The script's output is fully reproducible -- no `$RANDOM`, no
   timestamps that change between runs.
3. The script doesn't touch anything outside `$TMPDIR` / `/tmp`.

Then run `diff_oracle` on the new file alone to see whether lush matches.

## Adding scripts via harness (corpus/)

See [HARNESS.md](HARNESS.md) for the full ingest pipeline. The
short version:

```sh
tests/real_world/_harness/ingest.sh \
    --source-url https://example/upstream/path.sh \
    --upstream-commit abc1234 \
    --license SPDX-ID \
    --bucket posix|bash|zsh|lush \
    --upstream-set <name> \
    /path/to/candidate.sh
```
